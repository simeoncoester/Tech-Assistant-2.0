# Tech Assistent – Projektnotiz für Claude

Web-App für Musiker, Backliner und Toningenieure (Drum-Tuning, Stimmgerät, Setlisten, Showmodus, Clicktrack, Recording Recall, Backups). Live unter **https://simeoncoester.github.io/Tech-Assistant-2.0/** (GitHub Pages, Branch `main`, Wurzelordner).

Der Projektinhaber kommuniziert auf **Deutsch**, oft per Diktat (Tippfehler wie „Moritz“ = „Notiz“ sinngemäß lesen). Er schickt häufig Screenshots vom iPhone/iPad. Antworten kurz zusammenfassen: was geändert wurde, wie es sich bedienen lässt.

## Dateien

| Datei | Inhalt |
|---|---|
| `index.html` | Die komplette App: HTML, CSS und JavaScript in **einer** Datei, keine Frameworks, kein Build-Schritt |
| `manifest.webmanifest` | PWA-Manifest (Home-Bildschirm-App) |
| `sw.js` | Service Worker: Seite network-first mit `cache: 'no-store'`, Rest cache-first; Cache-Name bei SW-Änderungen hochzählen |
| `.github/workflows/pages-refresh.yml` | Fordert bei jedem Push auf `main` (oder manuell unter Actions) einen GitHub-Pages-Build an – Absicherung, falls GitHub die Veröffentlichung nach einem Push nicht selbst startet. Ein doppelter Lauf wird dabei abgebrochen („cancelled“), das ist normal |
| `tools/` | Prüfwerkzeuge (Playwright): `fp-check.js` Faceplate-Überschneidungen, `fp-legible.js` Schriftgröße auf dem iPhone, `fp-sheet.js`/`fp-shots.js` Screenshots, `tests/*.js` Regressionstests; Anleitung und Übergabe-Auftrag in `tools/HANDOFF.md` |
| `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` | App-Icons (Logo auf dunklem Grund) |

Externe Bibliotheken nur per CDN und erst bei Bedarf geladen: pdf.js, mammoth (Word), Tesseract.js 5.1.1 (Texterkennung), jsPDF 2.5.1. **Schriften lokal** (15.11.2026 (8), Datenschutz – keine Verbindung zu Google Fonts): `fonts/fonts.css` mit WOFF2-Dateien (Barlow 400/500/600, Barlow Condensed 500/600/700, je latin + latin-ext; Permanent Marker 400 latin), Lizenzen `fonts/OFL-Barlow.txt` und `fonts/LICENSE-PermanentMarker.txt`; `sw.js` cacht `fonts/fonts.css` (Cache `tech-assistent-v4`). Nie wieder Google-Fonts-Links einbauen.

## Release-Ablauf (bei jeder Änderung)

1. `APP_VERSION` in `index.html` hochzählen, Format `'TT.MM.JJJJ (n)'` (steht unten auf der Startseite).
2. JavaScript-Syntax prüfen (Script-Block extrahieren, `node --check`).
3. Testen in den Viewports 375×667, 390×844, 768×1024, 1024×1366, 1440×900: kein seitliches Scrollen, keine Überlappungen in `.grid`/`.row`/`.chips`, keine Knöpfe außerhalb ihrer Karte.
4. Betroffene Abläufe im Browser durchklicken (Playwright), Konsole ohne Fehler.
5. Commit mit kurzer deutscher Beschreibung, Push auf `main`.

## Datenmodell

```
S.artists[] → { id, name, logoV, fontV, fontName, wordmarkV, wordmarkRatio, productions[] }
production  → { id, mode: 'live'|'studio', kind, name, date, venue, kit, notes,
                drums[], mics[], chain[], setlists[], tunings[], instruments[], instChains, backups[], hasPhoto,
                kitId, kits[{id, name, (inaktive Kits zusätzlich: drums, mics, kit, hasPhoto, photoKey)}] }
setlist     → { id, mode, name, date, venue, info[{k,v}], cols[{name, type:'text'|'inst'}], design{key, cfg}, songs[] }
song        → { id, title, key, bpm, sig, note, sheet{…}, lyrics{…}, instNotes[{instId,name,inst,tuningId,tuning,capo,note}], extra{Spaltenname: Wert} }
```

- `normalize()` migriert ältere Datenstände automatisch – neue Felder dort absichern.
- Speicher: `localStorage` (`drumtech-v1` = Hauptdaten, außerdem Route, Theme, Sprache, Onboarding, Eingangswahl, Installationshinweis).
- Große Dateien (PDF-Sheets, Backup-Dateien, Fotos) in IndexedDB über `FileStore`; Logos/Schriften über `saveAsset`/`getAsset`; Kit-Fotos über `savePhoto`/`getPhoto`.
- `touch()` speichert und markiert Änderungen; `render(true)` zeichnet neu.

## Navigation

- `route` + `nav(view, patch)`. Ablauf: Künstler → Live/Studio → Tour/Produktion → Instrument → Funktionen.
- Wischen links/rechts wechselt Bereiche (auf dem Laptop auch Zweifinger-Wischen am Trackpad: horizontale `wheel`-Ereignisse in `initSwipe`, eine Geste = ein Wechsel; Nachschwung wird ignoriert (er wird nur schwächer); steigen die Werte zweimal hintereinander wieder an, gilt das als neue Geste; nach 450 ms Pause ist die Geste vorbei, `overscroll-behavior-x: none` gegen die Browser-Zurück-Geste), untere Leiste (`#tabbar`), Logo oben rechts = Startseite.
- Startseite: Künstler-Kacheln, darunter „Künstler hinzufügen“ und „Geteilte Daten übernehmen“ nebeneinander, Zahnrad oben in der Kopfzeile auf jeder Seite (zwischen „?“ und Logo, Klasse `gear-btn`) öffnet die Einstellungen (`settingsPop`: Design, Startsound, Sprache); Großansicht und Showmodus haben eigene Kopfzeilen ohne Zahnrad. Clicktrack und freier Drum-Tuner als kleine Symbole unten links/rechts in den Ecken (`.ft-corner`).
- Setlisten sind unabhängig vom Instrument-Bereich: derselbe Editor mit allen Feldern. „Tom-Tuning“ gibt es nur im Drumkit (dort mit Auswahl Setliste/Song), nicht im Song-Editor.
- Im freien Tuner Umschalter Drums/Bass/Gitarre in der Kopfzeile, Drums ist Standard.
- **Studio-Bereich mit Passwort** (auf github.io): Kachel „Studio · Mit Passwort“ öffnet `studioPwPop`, Passwort `STUDIO_PW = '12345'`; danach `localStorage drumtech-dev = 1` (einmal pro Gerät). Weiterhin freischalten per URL `#studio-freigeben`, sperren per `#studio-sperren`.
- **Geräte-Bibliothek ist global** (`S.devTpls`, Fotos in IndexedDB `dev-<id>`, `S.customGear`), gilt für alle Produktionen. Teilen: Produktionsdatei enthält `devPayload` (benutzte Geräte inkl. Fotos + alle eigenen Geräte `customGear`); `applyDevPayload` ersetzt gleiche Geräte-IDs mit dem geteilten Stand, ergänzt eigene Geräte, eine Gerätezuordnung bleibt beim eigenen Foto, falls schon eins für den Namen existiert. „Alle Geräte teilen“ in „Gespeicherte Fotos“ (`shareDevices`, Datei `type: 'devices'`, Empfang in `receivePayload`). Link-Teilen trägt keine Fotos, darum bei Produktionen mit Geräte-Fotos die Datei als Hauptknopf.
- **Total Recall** (Studio): in der Instrumentwahl (`viewInst`) steht im Studio statt der Setlisten-Schnellauswahl die Karte „Total Recall“ (`totalRecall()`). Eigener Recall pro Produktion unabhängig von den Instrumenten: `p.totalChain = { channels, busses }`, `route.chainOwner = 'total'` in `viewChain` und `consoleOwner`, Zurück führt zur Instrumentwahl; Mikrofonauswahl ohne Filter; `devTplsOf`/`devDelete` berücksichtigen `totalChain`. Live behält die Setlisten-Schnellauswahl.
- **Instrumente zwischen Live und Studio übertragen** (`instTransfer`, `xferSources`, `xferCopy`, Zustand `xferOpen`): Knopf „Instrumente aus Live/Studio übernehmen“ in der Instrumentwahl, nur wenn der andere Bereich des Künstlers Instrumente hat. Aufgeklappt: Dropdown mit Gruppen Gitarre, Bass, Schlagzeug aus allen Produktionen des anderen Bereichs. Gitarre/Bass werden mit neuer ID kopiert, die zugehörige Stimmung kommt mit, falls sie fehlt. Ein Drumkit füllt das leere aktuelle Kit, sonst wird ein weiteres Kit angelegt (neue Trommel-IDs, Mikrofone, Kit-Foto, eindeutiger Kit-Name). Das Original bleibt unverändert.
- **Knöpfe unten im Drumkit** (Live und Studio gleich): „Duplizieren“ legt eine Kopie des aktuellen Kits als weiteres Kit derselben Produktion an (`duplicateKit`: neue Trommel-IDs, Mikrofone, Kit-Foto, Name „… (Kopie)“), „Kit löschen“ mit Bestätigung (`delBtn`) löscht das Kit bzw. leert das einzige Kit (`clearKit`). „Produktion löschen“ gibt es dort nicht mehr (nur noch im Menü der Produktionsliste). Bei Gitarre/Bass hat jedes Instrument „Duplizieren“ (Kopie direkt dahinter, öffnet sie).
- **Mehrere Mikrofone pro Trommel/Instrument** (`multiMic`, `micsOf`): erstes Mikrofon in `d.mic` bzw. `i.ampMic`, weitere in `d.mics2` bzw. `i.ampMics2`; „+“ neben der Auswahl fügt eins hinzu, „×“ entfernt es, Beschriftung dann „Mikrofon 1/2 …“. Beim Übernehmen von Kanälen (`fromKit` in `viewChain`) gibt es pro Mikrofon einen Kanal („BD 1“, „BD 2“; Name frei änderbar). Im Total Recall heißt der Knopf „Kanäle aus Instrumenten übernehmen“ und öffnet eine Liste mit Checkboxen (`pickInstruments`): jedes Drumkit und jede Gitarre/jeder Bass einzeln, mit Anzahl der entstehenden Kanäle (Plan aus `chPlan.kit`/`chPlan.inst`: Amp-Mikrofone nummeriert, DI als „Name DI“), anfangs alle angehakt.
- **Recording Chain** heißt der Recall pro Instrument (Drums `p.chain`, Gitarre/Bass `P().instChains[inst]`): Kachel, Tab „Chain“, Seitentitel. Eigenes Symbol `ICON_PATHS.chain` (Geräte in Reihe mit Signalpfeil); Total Recall nutzt `ICON_PATHS.total` (Fader). Kein Mischpult bei Gitarre/Bass (nur Drums und Total Recall). In der Gitarren-/Bass-Chain „Kanäle aus Instrumenten übernehmen“ = `pickInstruments(route.inst)`: Checkboxen nur für die gespeicherten Instrumente dieser Art.
- **Verstärker-Auswahl** (`ampPicker`): wie Geräte/Mikrofone mit Hersteller → Modell, getrennte Listen `GEAR_DB['Gitarrenverstärker']` und `GEAR_DB['Bassverstärker']`, eigene Eingabe und „+ Eigenes Gerät hinzufügen“ landen in `S.customGear[...]` (über `learnGear`, wird mitgeteilt).
- **Total Recall übernimmt Recording Chains**: In `pickInstruments()` hängt die Drum-Chain am ersten Drumkit; Gitarren-/Bass-Chain-Kanäle hängen an dem Instrument, zu dem sie gehören (`ch.instId`, gesetzt beim Übernehmen aus Instrumenten in der Chain oder im Feld „Gehört zu Instrument“ `chInstField`; ohne Zuordnung per Namensanfang, `chInstOf`; `instId '-'` = bewusst keins). Kanäle ohne Instrument bekommen die eigene Zeile „Recording Chain ohne Instrument“. Die Unter-Checkbox „Recording Chain mit übernehmen“ erscheint nur, wenn es passende Kanäle gibt (`copyChain(src, nurDieseKanäle)`: Kanäle mit allen Stufen/Geräten und Busse mit umgemappten `srcIds` (bei Teilmengen nur Busse mit mindestens einer übernommenen Quelle), neue IDs, Mixer-Werte nicht übernommen; Kanäle/Busse mit gleichem Namen werden übersprungen). Danach werden die einfachen Kanäle pro Mikrofon ergänzt, gleichnamige bleiben weg.
- **Keine Setlisten im Studio**: Kacheln und Tabs nur im Live-Bereich, Routen `setlists`/`setlist` werden im Studio auf `inst` umgeleitet (`render`).
- **Reihenfolge der Kacheln und Tabs**: Drums Studio = Tuner, Drumkits, Recording Chain, Mischpult, Backup; Gitarre/Bass Studio = Tuner, Stimmungen, Instrumente, Recording Chain, Backup. Tabs genauso (Chain vor Backup). Live: Setlisten statt Chain/Mischpult, Backup zuletzt.
- **Startbildschirm schneller**: Logo-Animation und Startsound um ca. 30 % verkürzt (CSS-Delays `.lgx-*`, `spHit2`, `.sp-word`, `.sp-line`; Sound `D = 3.6`, `T = 1.25`, `END = 2.73`; Ausblenden nach 2,9 s, Fade 0,35 s). Sound und Animation bleiben synchron (`animPos` liest die laufende CSS-Animation).
- **Hilfe im Studio**: `pageHelpSlides` ersetzt bei `home`/`ghome` die Kachel-Übersicht (`STUDIO_TILES`, Setlisten → Recording Chain) und bei `inst` die Schritte (Recording Chain, „Instrumente aus Live übernehmen“).
- **Mischpult-Zugänge**: In der Recall-Ansicht läuft „Als Mischpult anzeigen“ beim Scrollen mit (`.mix-sticky`, sticky unter der Kopfzeile). In der Studio-Instrumentwahl steht unter „Total Recall“ die Kachel „Mischpult“ (`.total-mixer`, öffnet `console` mit `chainOwner: 'total'`). `route.consoleFrom` ('inst' | 'chain') steuert, wohin Zurück im Mischpult führt.
- **Potis drehen 360°**: `pos` bleibt 0 = 7 Uhr (Nullstellung), 1 = 5 Uhr (Winkel `-135 + pos*270`), erlaubt ist aber `PR_PMIN..PR_PMAX` (−1/6 bis 7/6 = −180° bis +180°, also bis ganz unten). Gilt für Ziehen, Schieberegler im Pop-up und Stellungserkennung (`prDetectPos` ohne Totzone). Alte Werte bleiben gültig.
- **Größenerkennung beim Regler-Setzen** (`prDetectSize`, gibt `{ r, x, y }` zurück und zentriert den Regler neu): Kantenbild pro Foto (`prPixCache[id].g`, 3×3 geglättet, Farbsprung über zwei Pixel), Flächenwachstum vom Tipp-Punkt über Pixel unter der Kantenschwelle (20, dann 34 und 52 für glänzende Kappen); Fehltreffer auf Zeiger/Beschriftung werden von Punkten rundum erneut versucht, ausgelaufene Flächen verworfen. Ein konzentrischer Ring (Rand/Skirt) wird mitgenommen. Testbild: Kappen auf wenige Pixel genau, auch bei Tipp außerhalb der Mitte.
- **Keine Lupe beim langen Drücken**: `.pr-ov` und `.pr-szbar` mit `user-select:none` und `-webkit-touch-callout:none`, `contextmenu` im Foto-Recall unterdrückt.
- **Hilfe-Folien Studio**: `HELP.chain` = Foto-Recall, „Regler selbst setzen“ (`prsetup`), Recording Recall, „Mono, Stereo, Dual Mono“ (`stwidth`), „Busse und Sends“ (`busses`), Schalter. In der Studio-Instrumentwahl ersetzt `TOTAL_SLIDE` (`totalrec`) die Setlisten-Folie (`pageHelpSlides`). `pageHelpSlides` wählt Folien per `art`, nicht per Index.
- **Mischpult-Inserts antippbar** (`button.ins`, `insOpen`): Stufe mit Geräte-Foto öffnet `showPhotoRecall` (grüner Punkt `.has-photo`), ohne Foto ein Pop-up mit den eingetragenen Werten.
- **Kein „Alles auf 0 dB“ im Mischpult**: der Knopf wurde entfernt, weil er alle Fader, Pan, Mute und Solo auf einmal zurücksetzte (zu gefährlich). Einzelne Fader/Potis setzt weiterhin ein Doppeltipp auf 0 dB.
- **Keine Plugins mehr**: `GEAR_DB` enthält nur Hardware, der Hardware/Plugin-Umschalter an der Stufe ist weg (`gearType` wird nicht mehr benutzt).
- **Faceplates** (`FACEPLATES`, `fpSvg`, `prBuiltinFor`): gezeichnete Frontplatten gängiger Klassiker (1176LN, LA-2A, Neve 1073, API 512c/550A/2500, Pultec EQP-1A/MEQ-5, dbx 160A, SSL G-Bus, Distressor EL8, Tube-Tech CL 1B, Manley Variable Mu, RE-201) mit fertig angelegten, beschrifteten Reglern. Schlüssel = exakter Gerätename aus `GEAR_DB`. Beim Wählen des Geräts legt `prAutoAttach` daraus ein normales Gerät an (`tpl.builtin = Gerätename`, id `fp-…`); `devPhoto` liefert das SVG als Data-URL, solange kein eigenes Foto gespeichert ist (eigenes Foto/„Foto ersetzen“ gewinnt, ebenso ein vorher gemachtes ungebundenes Foto). Beim Teilen werden die SVGs nicht mitgeschickt, der Empfänger zeichnet sie selbst. In der Schnellauswahl ▦ = Faceplate, 📷 = eigenes Foto. Neue Geräte: Eintrag in `FACEPLATES` mit `c: [Typ k/s/p, 'Name|LEGENDE', x, y, r, Farbe, Legendenposition a/b/l/r/n]`, `deco`-Elemente: `['vu', x, y, w, h, {face, dark, gr, label, needle}]` (Zeigerinstrument mit Skala; `dark` = schwarzes Zifferblatt, `gr` = Gain-Reduction-Skala 0–20), `['led', x, y, Ø, Farbe, an]`, `['leds', x0, y0, x1, y1, Anzahl, Ø, Farbe, leuchtende, Farbe der letzten zwei]` (LED-Kette/Meter), `['lamp', x, y, Ø, Farbe]` (Juwelen-Kontrolllampe), `['vmeter', x, y, w, h, {left, right, face}]` (senkrechtes Flachprofil-Instrument wie beim Neve 2254), `['rect', x, y, w, h, Füllung, Rahmen, rx]` (Sektionsrahmen/Gehäuse), `['poly', [[x, y]…], Farbe, Breite]` (Linienzug, z. B. Filterkurven), `noEars: true` = Desktop-Gerät ohne Rack-Ohren (Eckschrauben), `txt`, `vline`, `oval`. Ein `p` mit Farbe wird als farbiger Leuchttaster gezeichnet. Kompressoren aus Nutzerfotos (nur als Mess-Vorlage, neu gezeichnet): Fairchild 670, Chandler Zener Limiter, Neve 33609, API 527, Shadow Hills Mastering Compressor, Neve 2254 (Brent Averill 2254/E), dbx 165A, Preamps Focusrite ISA 428, Rupert Neve Designs Portico 511, Neve 1084, Grace Design m101, Neve 1073LB (500er), API 312, Avalon VT-737sp, Chandler TG2, Focusrite ISA One, Telefunken V76, Universal Audio 610 Solo, Universal Audio Apollo Twin X (neu in `GEAR_DB`), SSL VHD Pre (VHD+ 500), Great River MP-2NV, Rupert Neve Designs Shelford Channel, aus dem Studio des Nutzers: AML ez1073-pre, AML ezAM16-500, AML ez1073-pre Addon EQ, Klark Teknik 2A-KT, CAPI LC40, CAPI BT50, CAPI FC526, Sound Skulptor CP4500, Link Audio DYNX (SSL-Kompressor-Klon) und Link Audio SLQ (SSL-EQ-Klon) (alle auch neu in `GEAR_DB`); Distressor, dbx 160A, SSL G, Variable Mu und PE 1C haben Meter/LEDs/Lampen nachgerüstet bekommen. `fpSync(t)` gleicht ein schon angelegtes Faceplate-Gerät an, wenn sich der `FACEPLATES`-Eintrag ändert (`t.fpSig`; gleichnamige Regler behalten id und Wert). Das Plugin „SSL E-Series Kanal“ ist aus der Preamp-Liste entfernt. **Hardware-Optik:** `fpSvg` zeichnet gebürstetes Metall (gestreckte Turbulenz, Lichtverlauf, Fasen), Kreuzschlitzschrauben (`screw`), Rack-Ohren mit Langlöchern, weiche Schatten unter Reglern, hinterleuchtete VU-Meter mit Glas (Spiegelung, Innenschatten, Nadelschatten; `lit: 'amber'` für bernsteinfarbene Beleuchtung), LED-Linsen (`fpLed`) und Buchsen (`['jack', x, y, Ø]`); `bare: true` = ohne Schrauben (Kassette). Neue Channel Strips nach diesem Muster bauen. Prüfung neuer Faceplates zusätzlich: Text gegen Meterflächen und Regler gegen Rand/Meter. ## Scrollen

- Seiten sind genau so hoch wie der sichtbare Bereich unter der Kopfzeile: `main#app` `min-height: calc(100dvh - var(--hdr))`, `--hdr` misst `syncHdr()` nach jedem Rendern und bei Größenänderung; Platz für die schwebende Reiterleiste unten = deren echte Höhe (`--tabpad`). `overscroll-behavior: none` (nur auf Touch-Geräten! Am Mac/Safari blockiert es sonst das Trackpad-Scrollen; Desktop nur `overscroll-behavior-x: none`) verhindert den Gummiband-Effekt. Scrollen entsteht nur, wenn der Inhalt wirklich länger ist (Setlisten, Kit, Clicktrack, Formulare).
- **Untere Reiterleiste ist `position: sticky`, nicht `fixed` (12.11.2026 (1), Pflicht):** Auf dem iPhone löste sich die feste Leiste auf langen Seiten (Gitarren-Instrumente, Drum-Tuner mit offenen Einstellungen) und scrollte mit dem Inhalt mit. `#tabbar` steht deshalb am Ende des Seitenflusses und klebt per `sticky` mit `bottom` = Safe-Area + 10 px unten (gleicher Abstand als `margin-bottom`, damit er auch am Seitenende bleibt; ab 800 px Breite `max-width: 732px`, zentriert). Die Leiste braucht dadurch eigenen Platz: `body.has-tabs main#app` hat nur noch 14 px Innenabstand unten und `min-height: 100dvh − --hdr − --tabpad + 14px`; `--tabpad` = Leistenhöhe + unterer Abstand + 14 px (`syncHdr`, aus `offsetHeight` statt aus der Bildschirmposition). Kurze Seiten bleiben genau bildschirmhoch. `tools/tests/tab.js` prüft in beiden Designs, dass die Leiste beim Scrollen unten bleibt (erwartet „TAB OK“). Keine neuen `position: fixed`-Leisten für Seiteninhalt bauen.
- Tuner-Seiten passen ohne Scrollen: Einstellungen (inkl. Lug-Anzahl, Reihenfolge, Auto-Weiter, Empfindlichkeit, Eingang) sind eingeklappt, die Trommeln richten ihre Größe nach der Bildschirmhöhe (`max-height` mit `100dvh`), auf kurzen Bildschirmen (≤ 760 px hoch) ist das Frequenzspektrum ausgeblendet.

- Kopfzeile: Band-Identität über `hdrIdent` (Schriftzug, sonst Name; Logos bleiben in den Kacheln) in konstanter Größe, mit oder ohne Tour; ab 1024 px Breite größere Kopfzeile. Zurück-Knopf als Pfeil-Symbol. Seiteninhalt steckt in `#app > .app-in` und wird bei kurzen Seiten vertikal zentriert (lange Seiten beginnen oben).
- Live = Rot, Studio = Blau. Kacheln ohne Erklärungstext (Erklärungen gehören in die Hilfe).
- Längliche Karten: ≡-Menü rechts (Umbenennen/Löschen mit Bestätigung), gedrückt halten = sortieren.
- Typografische Anführungszeichen im deutschen Text („…“), Apostroph ’.
- Layout-Sicherheit: Grid-Spalten mit `minmax(0,1fr)`, Felder `min-width: 0` (iOS-Datumsfelder!).

## Bekannte Grenzen

- `window.claude` (Bild-/Texterkennung durch Claude, Synchronisation) gibt es nur innerhalb von claude.ai. Auf GitHub immer eine Alternative auf dem Gerät anbieten.
- Daten liegen lokal pro Gerät; Safari und Home-Bildschirm-App speichern getrennt.
- Studio-Bereich ist noch in Arbeit.
