# Tech Assistent – Projektnotiz für Claude

Web-App für Musiker, Backliner und Toningenieure (Drum-Tuning, Stimmgerät, Setlisten, Showmodus, Clicktrack, Recording Recall, Backups). Live unter **https://simeoncoester.github.io/Tech-Assistant-2.0/** (GitHub Pages, Branch `main`, Wurzelordner).

Der Projektinhaber kommuniziert auf **Deutsch**, oft per Diktat (Tippfehler wie „Moritz“ = „Notiz“ sinngemäß lesen). Er schickt häufig Screenshots vom iPhone/iPad. Antworten kurz zusammenfassen: was geändert wurde, wie es sich bedienen lässt.

## Dateien

| Datei | Inhalt |
|---|---|
| `index.html` | Die komplette App: HTML, CSS und JavaScript in **einer** Datei, keine Frameworks, kein Build-Schritt |
| `manifest.webmanifest` | PWA-Manifest (Home-Bildschirm-App) |
| `sw.js` | Service Worker: Seite network-first mit `cache: 'no-store'`, Rest cache-first; Cache-Name bei SW-Änderungen hochzählen |
| `.github/workflows/pages-refresh.yml` | Fordert bei jedem Push auf `main` (oder manuell unter Actions) einen GitHub-Pages-Build an – Absicherung, falls GitHub die Veröffentlichung nach einem Push nicht selbst startet. Ein doppelter Lauf wird dabei abgebrochen („cancelled“), das ist normal |
| `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` | App-Icons (Logo auf dunklem Grund) |

Externe Bibliotheken nur per CDN und erst bei Bedarf geladen: pdf.js, mammoth (Word), Tesseract.js 5.1.1 (Texterkennung), jsPDF 2.5.1, Google Fonts (Barlow, Barlow Condensed, Permanent Marker).

## Release-Ablauf (bei jeder Änderung)

1. `APP_VERSION` in `index.html` hochzählen, Format `'TT.MM.JJJJ (n)'` (steht unten auf der Startseite).
2. JavaScript-Syntax prüfen (Script-Block extrahieren, `node --check`).
3. Testen in den Viewports 375×667, 390×844, 768×1024, 1024×1366, 1440×900: kein seitliches Scrollen, keine Überlappungen in `.grid`/`.row`/`.chips`, keine Knöpfe außerhalb ihrer Karte.
4. Betroffene Abläufe im Browser durchklicken (Playwright), Konsole ohne Fehler.
5. Commit mit kurzer deutscher Beschreibung, Push auf `main`.

## Datenmodell

```
S.artists[] → { id, name, logoV, fontV, fontName, wordmarkV, wordmarkRatio, productions[] }
production  → { id, mode: 'live'|'studio', kind, name, date, venue, kit, notes,
                drums[], mics[], chain[], setlists[], tunings[], instruments[], instChains, backups[], hasPhoto,
                kitId, kits[{id, name, (inaktive Kits zusätzlich: drums, mics, kit, hasPhoto, photoKey)}] }
setlist     → { id, mode, name, date, venue, info[{k,v}], cols[{name, type:'text'|'inst'}], design{key, cfg}, songs[] }
song        → { id, title, key, bpm, sig, note, sheet{…}, lyrics{…}, instNotes[{instId,name,inst,tuningId,tuning,capo,note}], extra{Spaltenname: Wert} }
```

- `normalize()` migriert ältere Datenstände automatisch – neue Felder dort absichern.
- Speicher: `localStorage` (`drumtech-v1` = Hauptdaten, außerdem Route, Theme, Sprache, Onboarding, Eingangswahl, Installationshinweis).
- Große Dateien (PDF-Sheets, Backup-Dateien, Fotos) in IndexedDB über `FileStore`; Logos/Schriften über `saveAsset`/`getAsset`; Kit-Fotos über `savePhoto`/`getPhoto`.
- `touch()` speichert und markiert Änderungen; `render(true)` zeichnet neu.

## Navigation

- `route` + `nav(view, patch)`. Ablauf: Künstler → Live/Studio → Tour/Produktion → Instrument → Funktionen.
- Wischen links/rechts wechselt Bereiche (auf dem Laptop auch Zweifinger-Wischen am Trackpad: horizontale `wheel`-Ereignisse in `initSwipe`, eine Geste = ein Wechsel; Nachschwung wird ignoriert (er wird nur schwächer); steigen die Werte zweimal hintereinander wieder an, gilt das als neue Geste; nach 450 ms Pause ist die Geste vorbei, `overscroll-behavior-x: none` gegen die Browser-Zurück-Geste), untere Leiste (`#tabbar`), Logo oben rechts = Startseite.
- Startseite: Künstler-Kacheln, darunter „Künstler hinzufügen“ und „Geteilte Daten übernehmen“ nebeneinander, Zahnrad oben in der Kopfzeile auf jeder Seite (zwischen „?“ und Logo, Klasse `gear-btn`) öffnet die Einstellungen (`settingsPop`: Design, Startsound, Sprache); Großansicht und Showmodus haben eigene Kopfzeilen ohne Zahnrad. Clicktrack und freier Drum-Tuner als kleine Symbole unten links/rechts in den Ecken (`.ft-corner`).
- Setlisten sind unabhängig vom Instrument-Bereich: derselbe Editor mit allen Feldern. „Tom-Tuning“ gibt es nur im Drumkit (dort mit Auswahl Setliste/Song), nicht im Song-Editor.
- Im freien Tuner Umschalter Drums/Bass/Gitarre in der Kopfzeile, Drums ist Standard.
- **Studio-Bereich ist für Tester gesperrt** („Under Construction“). Freischalten per URL `#studio-freigeben`, sperren per `#studio-sperren`.

## Wichtige Bereiche im Code

- **Tuner** (`Tuner`-Objekt): Drums (Lugs, Pitch, Resonanz) – ein einziger Drum-Tuner (früheres „Quick Tuning“ ist darin aufgegangen; alte Route `quick` leitet auf `tuner`/Lugs um). Ohne gespeicherte Trommel Auswahl „Trommelgröße“ (`route.qSize`, setzt den Frequenzbereich über `quickRange`), Schalter „Automatisch zur nächsten Schraube“ (`route.L.auto`). Lug-Referenz: Antippen einer Schraube macht sie zur Referenz (`L.ref`, gespeichert als `drum.lugRef`), sie bekommt die Nummer 1 und einen blauen Ring; die Zahlen an der Trommel zeigen die Reihenfolge (`lugOrder(n, pattern, ref)`, Uhrzeigersinn oder Sternmuster ab der Referenz), die nächste Schraube pulsiert gelb. Einstellungen des Drum-Tuners (Trommel, Größe, Fellseite, Zielfrequenz, Frequenzbereich, Empfindlichkeit) sind eingeklappt: Knopf oben rechts in der Trommel-Karte jedes Reiters (`.dt-set`, `route.dSet`), das Feld erscheint unter der Karte des offenen Reiters (`placeSettings`); Stimmschrauben, Reihenfolge und Auto-Weiter erscheinen nur im Reiter Lugs (`.dt-lugonly`); Speichern-Knöpfe nur mit gespeicherter Trommel. Bei Resonanz leuchtet das Fell, das als Nächstes gemessen wird, grün (wie die gewählte Saite). Standard: Schlagfell, Frequenzbereich „Alles“. Kleingedruckte Tipps in Tunern und Clicktrack sind entfernt, die Infos stehen in den Hilfe-Folien. Reiter Pitch (ohne Liste „Letzte Schläge“) zeigt eine runde Trommel (`pitchDrum`, gleiche Optik wie `drumGraphic`): Hz in der Mitte, Note und Ziel darunter, Status oben, Bogen-Anzeige am Rand (±50 Cent, grüne Zone ±8 Cent), Trommel leuchtet grün bei „Stimmt“; die allgemeine Hz-Anzeige über den Reitern ist in allen Reitern ausgeblendet (die Trommeln zeigen die Werte). Lug-Trommel (`drumGraphic`, viewBox 400, füllt die Kartenbreite bis 460 px): Referenz-Hz groß in der Mitte, außen neben jeder Schraube Cent-Abweichung und darunter (oben: darüber) die Frequenz; Farben: grün = innerhalb ±5 Cent, rot = zu tief, blau = zu hoch (Schraubennummer und Texte). Bass/Gitarre (YIN) mit Display `gtDisplay` (eigenes Design im Stil klassischer Stimmgeräte: LED-Bogen aus 21 Segmenten à 5 Cent, füllt sich rot von der Mitte zur Abweichung, grün in der Mitte bei ±3 Cent; VU-Skala mit Nadel; große Note mit kleiner Oktave in der Mitte; Hz/Saite und Cent unten). Gewählte Saite (`.str[aria-pressed=true]`) leuchtet grün; erneutes Antippen wählt sie ab (zurück zu „Automatisch“). Stimmung, Referenz A4 und Saitenwahl sind eingeklappt und öffnen über den Einstellungsknopf oben rechts im Display (`.gt-set`, `route.gSet`); oben links im Display steht die aktuelle Stimmung mit A4. Mikrofon ohne Echo-/Rauschunterdrückung. `Tuner.start` stellt auf iPhone/iPad die Audio-Sitzung auf `play-and-record` (Startsound/Click setzen `ambient`/`playback`, das blockiert sonst das Mikrofon; `stop` setzt `auto`) und versucht nacheinander: gewählter Eingang, Standard-Eingang mit Einstellungen, einfaches `{ audio: true }`. Fehlertexte nach Ursache (`micErr`/`showMicErr`, mit technischem Code in Klammern), keine pauschale „im Browser öffnen“-Meldung mehr. Eingangswahl und Pegelanzeige (`inputPanel`, `Tuner.inputId`, `Tuner.inputLevel()`) für Gitarren-Adapter/Interfaces.
- **Mehrere Drumkits pro Produktion** (`ensureKits`, `activateKit`, `addKit`, `deleteKit`, `viewKitList`, `openKits`): das gewählte Kit liegt wie früher direkt an der Produktion (`drums`, `mics`, `kit`, `hasPhoto`, `photoKey` = `KIT_FIELDS`), weitere Kits stecken komplett in `p.kits`; `activateKit` tauscht die Daten. So arbeiten Tuner, Tom-Tuning, Recording Recall und Kit-Foto unverändert mit `p.drums`. Kit-Fotos haben pro Kit einen eigenen Schlüssel (`phId` = `photoKey` oder beim ersten Kit die Produktions-ID). „+“ oben rechts im Drumkit legt ein Kit an; ab zwei Kits öffnen Kachel/Reiter „Kit“ zuerst die Kit-Liste. Oben in jedem Kit und jedem Instrument (`ginst`) steht eine kleine Übersicht (`.kit-bar`: Name, Punkte, „+“ für ein weiteres Kit bzw. Instrument). In der Kit-Ansicht (bei mehreren Kits) und bei Instrumenten (Gitarre/Bass, `ginst`) wechselt Wischen zwischen den Kits bzw. Instrumenten statt zurückzublättern (`swipeNeighbors`); zurück nur über den Pfeil. Der Tuner listet die Trommeln aller Kits und aktiviert beim Wählen das passende Kit.
- **Foto-Recall** (Studio, Recording Recall; `prPick`, `showPhotoRecall`, `prControlPop`, `photoRecallRow`, `devImage`, `devPhoto`): an jeder Stufe „📷 Foto-Recall“. Gerätevorlagen global in `S.devTpls = [{ id, name, kind, ctrls: [{ id, name, type: 'knob'|'switch', x, y }] }]` (x/y relativ 0–1), Foto in IndexedDB (`FileStore`, Schlüssel `dev-<id>`, bis 1800 px), Werte in der Stufe: `st.photo = { tplId, vals: { ctrlId: { pos 0–1, text } | { on } } }`. Editor im Vollbild (`.pr-ov`, z-index 30 unter den Pop-ups): Modus „Regler setzen“ (Foto antippen = Regler anlegen, Ziehen = verschieben, Antippen = Name/Art/Löschen) und „Einstellen“ (Ziehen = drehen, −135°…+135°, Anzeige als Uhrzeit; Antippen = Pop-up mit Stellung und genauem Wert; Schalter An/Aus). Fotos reisen beim Teilen nicht mit.
- **Tuning-Empfehlung** (`planTuning`, `showTuningSheet`): nur Toms (Snare/Bassdrum ausgeschlossen). Modi Setliste (Durchschnitt oder einzelner Song), Tonart, Intervalle. Schieberegler tief–hoch (`level`). Realistische Bereiche in `TOM_RANGE` (angelehnt an Tune-Bot; 16″ bis 60 Hz). Intervalle nach Kesselgröße: `ivBySize`.
- **Clicktrack** (`Click`): synthetisierte Sounds, Taktart, Betonungen, Unterteilung, Ausgabe akustisch/optisch. Optischer Impuls: alle Zählzeiten gleich hell, Betonung rot, BPM-Zahl blendet beim Laufen aus.
- **Setlisten**: Im Setlisten-Editor klappt nur das „≡“ am Song den Editor auf (`.handle`, `onclick: toggle`); Antippen des übrigen Song-Kopfs tut nichts, Verschieben überall am Song-Kopf: Touch = kurz gedrückt halten (320 ms), Maus = drücken und ziehen ohne Wartezeit (`enableReorder(…, { handleDrag: false, mouseDrag: true, pressMs: 320 })`). Play-Knöpfe der Setlisten-Karten: roter Rand, zarte Tönung. Kachel/Reiter heißen „Drumkits“/„Kits“, bei Bass/Gitarre „Tuner“ statt „Stimmgerät“. Song-Editor in dieser Reihenfolge: Titel/BPM/Takt, Tonart, Instrument-Kacheln (gespeichertes Instrument oder „ohne festes Instrument“ Gitarre/Bass; jede Kachel mit Stimmung-Auswahl inkl. Vorlagen und „Eigene …“, Kapo und Notiz – es gibt keine separate Song-Stimmung mehr, alte Felder `gt`/`bs` migriert `normalize()` in Kacheln; `stageTun` fasst die Stimmungen für Großansicht/Showmodus zusammen; gestrichelte „+ Notiz“-Kachel, Antippen öffnet mittiges Pop-up `instNoteDialog` für eine Instrument-Notiz wie „Chorus 1“, Feld `instNotes[].note`, erscheint auch in Großansicht/Showmodus), Notiz (dezenter Hinweis auf „/“ beim Fokus), „Chords und Lyrics“ (Chordsheet und Songtext: Datei oder Foto, auch handschriftlich, bearbeitbar, PDF-Export).
- **Import** (`importButton`, `importSetlistPhoto`, `parseSetlistMeta`, `parseSongs`, `parseSongLine`): erkennt Name, Datum, Ort und Spaltenköpfe. Fotos: in claude.ai liest Claude (`window.claude`), sonst Tesseract mit Vorverarbeitung (`ocrPrepare`: Median-Filter gegen Druckraster, Kontrast, Otsu-Schwelle; `cleanOcrLines`).
- **PDF-Tabellen-Import** (`pdfTable`, `tableMeta`, `tableSongs`, `tableDesign`, `TBL_HEAD`/`TBL_LOOSE`, `TBL_KINDS`): erkennt die Kopfzeile (auch zusammengesetzte Namen wie „Backline-Notizen“) und ordnet Text per x-Position den Spalten zu. Tabellenzeilen werden über Zeilenabstände gebildet (Titel darf vertikal mittig stehen), in nummerierten Tabellen beginnt jede Nummer eine Zeile. „–“ gilt als leer; Zugabe-/Pause-Zeilen markieren Songs und hängen ihre Notiz an den nächsten Song; Fußzeilen und Seitenzahlen werden ignoriert. Mehrzeilige Zellen eigener Spalten werden mit „ · “ gespeichert und zeilenweise angezeigt (`xLines`). Kopfbereich „Label: Wert“ → Datum, Ort, übrige Angaben in `setlist.info[{k,v}]` (Editor-Felder, Großansicht-Kopf). Unbekannte Spalten → `song.extra[name]`. Optional Design „Wie PDF: …“. Ohne Tabelle greift die normale Texterkennung. Testbeispiel: echte Backline-Setliste mit 10 Spalten.
- **Eigene Spalten** (`slCols`, `newColDialog`, `colMenu`, `instSelect`): pro Setliste in `s.cols` definiert (Text oder Instrument aus `P().instruments`), Werte in `song.extra[name]`; im Song-Editor gestrichelte Kachel „+ Eigene Spalte erzeugen“, „⋯“ am Feld zum Umbenennen/Löschen (für alle Songs). Importierte Spalten werden ebenfalls als `s.cols` angelegt. In der Großansicht zeigen die Vorschläge „Karten“ und „Tabelle“ eigene Spalten automatisch.
- **Großansicht-Layouts** (`ST_PRESETS`, `stLoad`/`stSave`, Schlüssel `drumtech-stage-layout` pro Gerät: `{ active, saved: [{ id, name, cfg }] }`): **Jede Setliste hat ihr eigenes Design** in `setlist.design = { key, cfg }` (Kopie der Einstellungen, `stDesignOf`); die gespeicherten Designs sind nur eine Bibliothek zum Auswählen. Auswählen, „Speichern unter …“ und „Änderungen speichern“ wirken nur auf die offene Setliste (Bibliothekseintrag wird aktualisiert, andere Setlisten behalten ihre Kopie). `stSnapshotAll` gibt Setlisten ohne eigenes Design beim ersten Öffnen das bisher globale Design (`active`), das danach nicht mehr verändert wird. PDF-Import: `tableDesign` liefert das Design für die neue Setliste. Vorschläge Karten, Tabelle, Kompakt, Bühne + beliebig viele eigene Designs. Knopf „Ansicht“ öffnet `stagePanel` mit zwei Reitern (`stPanTab`): „Design wählen“ (Vorschläge, Meine Designs, Umbenennen/Löschen) und „Anpassen“ (Darstellung, Schriftgröße, Zeilenhöhe, Spaltenliste; Farbe und Breite einer Spalte klappen erst über den Knopf mit Farbpunkt ▾ auf, `stOpenCols`). Status und Speichern stehen in beiden Reitern unten. Anpassungen sind nur Vorschau (`temp`, bis die Großansicht schließt), gespeichert wird nur über „Speichern unter …“ (Name per `namePop`) bzw. „Änderungen speichern“; „Fertig“ speichert nichts. Spaltenbreiten per Regler (`cfg.widths[k]` 0,5–3, skaliert Mindestbreite und fr-Anteil über `stW`/`stMinW`), Zeilenhöhe per Regler (`cfg.pad` 2–44 px; ersetzt die alten Abstand-Stufen `dens`). Die sichtbare Texthöhe in `.clip` wächst mit der Zeilenhöhe; `stMarkClipped` misst bei jeder Änderung neu und blendet „mehr“/„weniger“ aus, sobald der Text ganz passt (aufgeklappte Zeilen werden dann zugeklappt). Spaltenfarben gelten auch im Showmodus (`stLiveCfg` = Design der offenen Großansicht, sonst aktives Design). Hilfe: `HELP.stage` (Knopf „?“ in der Großansicht), Folien `pdfimp`, `stview`, `stedit`. Regler zeigen beim Ziehen eine Live-Vorschau (`live`), speichern erst beim Loslassen den Status. Lange Texte (Notizen, eigene Spalten) stecken in `.clip` (max. 3 Zeilen); Antippen von gekürztem Text oder „mehr ▾“ klappt die ganze Zeile auf (`stToggleRow`, Klasse `xp`, `stNoteOpen`), sonst öffnet Antippen den Showmodus. `stMarkClipped` misst nach dem Zeichnen, nach `document.fonts.ready` und per ResizeObserver. Knopf „Bearbeiten“ in der Großansicht: Antippen eines Wertes (`data-c`) öffnet `editPop` über `stEditField`; leere Felder der Tabelle (Klasse `st-blank`) zeigen im Bearbeiten-Modus ein „+“ und lassen sich per Tipp oder Doppeltipp füllen (Tipp irgendwo in der Spalte der Zeile trifft das Feld; `editPop` ignoriert den zweiten Tipp eines Doppeltipps); Setlisten-Name, Ort und Info-Kacheln sind ebenfalls bearbeitbar. Im Song-Editor sind Notiz und eigene Felder mitwachsende Textfelder (`autoGrow`); mehrzeilige Werte eigener Spalten werden als „ · “ gespeichert. Farbe pro Spalte (`cfg.colors`, Palette `ST_PALETTE`, Auswahl über `colorPop`) färbt Schrift und Kacheln der Spalte (Klasse `cc`, Variable `--cc`). `dragSort` verschiebt Zeilen (Song-Reihenfolge, wird gespeichert) und Spaltenköpfe (nur Vorschau). Touch: gedrückt halten, Maus: drücken und ziehen.
- **Schnellstart** (`setlistCard`, `startChoice`): ▶ auf einer Setlisten-Karte fragt „Großansicht“ oder „Showmodus“; beides öffnet sich als Overlay, Schließen führt zurück zur Auswahl. Im Setlisten-Editor gibt es „Großansicht“ oben neben „Songs“ und unten.
- **Großansicht** (`showStage`) und **Showmodus** (`showStageSong`): immer schwarz; solange eines davon offen ist, schaltet `darkWhile` das ganze Erscheinungsbild auf Dunkel (auch Pop-ups, Ansicht-Fenster, Hilfe) und stellt danach Hell wieder her. Titel zentriert, Nummer links. Kopfzeile der Großansicht auf Handys (≤ 600 px): fünf gleich hohe 40-px-Knöpfe in einer Reihe (Ansicht und Bearbeiten nur als Symbol), unter 360 px rutscht „Showmodus“ in eine eigene zweite Reihe. Click-Pille mit Schloss (lange drücken = entsperren, temporäre Werte; Schließen = zurück auf gespeicherte Werte; bei Songs ohne Tempo wird beim Schließen gespeichert). Chords unten links, Lyrics unten rechts. Notizen mit „/“ getrennt = eigene Kacheln, Doppeltipp blendet aus.
- **Stimmungen Bass/Gitarre** (`viewTunings`, `viewTuning`, `TEMPLATES`): Vorlage wählen oder „Eigene erstellen“ → Pop-up `tuningDialog(inst, onSave, onCancel)` (Name, Saiten, Kapo; speichert in `P().tunings`). Dasselbe Pop-up über „Eigene …“ bei der Standard-Stimmung eines Instruments und „+ Eigene Stimmung erstellen …“ im Tour-Tuner. Der freie Tuner zeigt alle eigenen Stimmungen aller Touren (`allSavedTunings`).
- **Backups** (`viewBackups`): pro Produktion und Instrument, Gerätelisten `BACKUP_DEVICES` (Bass/Gitarre) und `BACKUP_DEVICES_DRUMS`.
- **Teilen** (`shareArtistDialog`, `shareProductionDialog`, `receivePayload`, `applyArtistPayload`, `applyPayload`): ganzer Künstler oder einzelne Tour, Künstlerprofil (Logo, Schrift, Schriftzug) reist immer mit. Link (`#import=` gzip) oder Datei (`.techassistent.json`).
- Hilfe-Knopf der Startseite: Logo als dünne Leuchtlinie (`glassLogo`, Klasse `saber-logo`: sehr dünner hellblauer Kern, darum per Gauß-Unschärfe ein dunkler, verwaschener blauer Schein), „?“ mit Farbwechsel wie die anderen Fragezeichen.
- **Hilfe**: `START_SLIDES` (Startseite, 4 Folien), `HELP.ghome` als Rundgang für Bass/Gitarre (Übersicht mit Symbol-Kacheln `tiles4`, „Instrument anlegen“ `ginstnew` mit animierter Menüführung über `seMenu`, Stimmungen, Stimmgerät, Instrumente pro Song), `HELP[view]` (Kontexthilfe), Grafiken in `ARTS`, Animationen in `DEMOS`, Folien über `SL(art, demo, title, text, steps, extra)`. Keine Stichpunkt-Listen: Die `steps` einer Folie erscheinen als eine Bildunterschrift (`.onb-cap`) unter der Animation, die pro Demo-Schritt wechselt (alle 2,6 s, Fortschritt als kleine Balken `.onb-capdots`); die Animation läuft in Schleife (`runDemo`, `capOf`). Ohne `steps` läuft die Demo automatisch. Neue Funktionen immer auch in den Folien zeigen.
- **Startsound** (`StartSound`): dezenter „Power-on-Buzz“ wie bei Logo-Sounds von Automarken (warme, leicht verstimmte Sägezahn-Töne um 55 Hz durch sich öffnenden Tiefpass, Sub-Basis, leichtes 29-Hz-Brummen, keine harten Schläge: beim Einrasten (1,78 s) blüht der Klang sanft auf, leiser luftiger Oberton; Whooshes der Logo-Teile und Übergang zur App nur als sehr leiser Hauch; Spitzenpegel ca. 0,26), per `OfflineAudioContext` einmal gerendert und synchron zur Splash-Animation abgespielt. Ist Ton sofort erlaubt, wartet die Animation (Klasse `hold`, max. 0,7 s) und beide starten gemeinsam; sonst startet der Ton beim ersten Antippen an der Position der laufenden Animation (iOS gibt Ton erst beim Loslassen frei: Ereignisse `touchend`/`click` werden mitgehört; kein Hinweis auf dem Splash – auf dem iPhone bleibt der Startsound ohne Antippen still). `audioSession.type = 'ambient'` (respektiert den Lautlos-Schalter). Schalter „Startsound An/Aus“ im Einstellungen-Pop-up der Startseite (`drumtech-startsound`).
- **PWA**: `registerSW` (nicht in claude.ai), Installationshinweis auf der Startseite (nur im Browser).

## Mehrsprachigkeit (Pflicht bei jeder Textänderung)

- Deutsch ist die Quellsprache im Code. Übersetzt wird zur Laufzeit ins Englische, Spanische und Französische.
- Wörterbuch `I18N` (eine Zeile JSON): `"Deutscher Text": ["English", "Español", "Français"]`. **Jeder neue sichtbare Text braucht einen Eintrag.**
- Dynamische Texte über Regex-Muster in der Musterliste (vor dem letzten Eintrag `/^(.+) – Tech Assistent$/` einfügen), Hilfsfunktion `L3(en, es, fr)`.
- Eigene Eingaben (Namen, Titel, Notizen) nicht übersetzen: Selektor `NO_I18N` bzw. Klasse `no-i18n`.
- Tonarten lokal (`keyLocal`), Zahlen und Datum im Landesformat.

## Scrollen

- Seiten sind genau so hoch wie der sichtbare Bereich unter der Kopfzeile: `main#app` `min-height: calc(100dvh - var(--hdr))`, `--hdr` misst `syncHdr()` nach jedem Rendern und bei Größenänderung; Platz für die schwebende Reiterleiste unten = deren echte Höhe (`--tabpad`). `overscroll-behavior: none` (nur auf Touch-Geräten! Am Mac/Safari blockiert es sonst das Trackpad-Scrollen; Desktop nur `overscroll-behavior-x: none`) verhindert den Gummiband-Effekt. Scrollen entsteht nur, wenn der Inhalt wirklich länger ist (Setlisten, Kit, Clicktrack, Formulare).
- Tuner-Seiten passen ohne Scrollen: Einstellungen (inkl. Lug-Anzahl, Reihenfolge, Auto-Weiter, Empfindlichkeit, Eingang) sind eingeklappt, die Trommeln richten ihre Größe nach der Bildschirmhöhe (`max-height` mit `100dvh`), auf kurzen Bildschirmen (≤ 760 px hoch) ist das Frequenzspektrum ausgeblendet.

## Design-Regeln

- Dunkles Design als Standard, helles Design über Klasse `ice`. Farben als CSS-Variablen.
- Glas-Optik: halbtransparente Flächen, feiner heller Rand, leichter Glanz oben. Rundungen moderat, keine Pillen: Knöpfe 12 px (klein 10 px), Chips/Plaketten 8 px, Karten 12 px, Kacheln 14 px (Block „calmer corner radii“ am CSS-Ende).
- Knopf-Rollen: weiterführend (`.btn.nav`, z. B. Großansicht, Ansehen, Stimmen) = blauer Rand; löschen/entfernen (`.btn.danger`, `.btn.del`) und laufendes Beenden (`.stop`, Clicktrack „Stopp“) = dunkelroter Rand.
- Hauptknöpfe (`.btn.solid`, aktive Chips/Segmente, `.btn.solid.accent`): kräftiger farbiger Rand (1,5 px), innen nur zarte Tönung, helle Schrift (hell: dunkelblaue Schrift). Keine vollflächig gefüllten Knöpfe. Regeln im Block „refined primary buttons“ am Ende des CSS.
- Kopfzeile: Band-Identität über `hdrIdent` (Schriftzug, sonst Name; Logos bleiben in den Kacheln) in konstanter Größe, mit oder ohne Tour; ab 1024 px Breite größere Kopfzeile. Zurück-Knopf als Pfeil-Symbol. Seiteninhalt steckt in `#app > .app-in` und wird bei kurzen Seiten vertikal zentriert (lange Seiten beginnen oben).
- Live = Rot, Studio = Blau. Kacheln ohne Erklärungstext (Erklärungen gehören in die Hilfe).
- Längliche Karten: ≡-Menü rechts (Umbenennen/Löschen mit Bestätigung), gedrückt halten = sortieren.
- Typografische Anführungszeichen im deutschen Text („…“), Apostroph ’.
- Layout-Sicherheit: Grid-Spalten mit `minmax(0,1fr)`, Felder `min-width: 0` (iOS-Datumsfelder!).

## Bekannte Grenzen

- `window.claude` (Bild-/Texterkennung durch Claude, Synchronisation) gibt es nur innerhalb von claude.ai. Auf GitHub immer eine Alternative auf dem Gerät anbieten.
- Daten liegen lokal pro Gerät; Safari und Home-Bildschirm-App speichern getrennt.
- Studio-Bereich ist noch in Arbeit.
